# DARE Run Plan: External Baselines (2026-10-19)

Four external systems, all on `deepseek-v4-flash`, run on the same benchmarks as the main experiment. The results are placed against DARE later. That comparison is out of scope here.

Companion plan: `2026-10-19-dare-run-plan-deepseek-glm.md`. Both plans use the same benchmarks and the same deliverable layout.

## 1. Conditions

| Condition ID | System | Runtime | Benchmarks |
| --- | --- | --- | --- |
| `dsh.deepseek-v4-flash.aris` | [ARIS](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep) | dsh with the `dsh-aris` plugin | Lit2Test, PaperGym-Design |
| `researchstudio-idea.deepseek-v4-flash.ideaspark` | [ResearchStudio-Idea](https://github.com/microsoft/ResearchStudio/tree/main/ResearchStudio-Idea) | its `run.py` with a CLI shim to the model | Lit2Test, PaperGym-Design |
| `ai-scientist-v2.deepseek-v4-flash.ideation` | [AI Scientist v2](https://github.com/SakanaAI/AI-Scientist-v2) | Python, ideation stage only | Lit2Test, PaperGym-Design |
| `dsh.deepseek-v4-flash.scientific-skills` | [claude-scientific-skills](https://github.com/K-Dense-AI/claude-scientific-skills) | dsh | All four |

The three AI scientist systems produce research proposals, so they run only the two generation benchmarks. claude-scientific-skills is a loose skill pack, the same form as DARE, so it runs all four.

Rules for all four conditions:

- **One model everywhere.** The executor model is `deepseek-v4-flash`. The one exception is ARIS's reviewer, which stays on gpt-6-astra.
- **Online retrieval is off.** No web search, no web fetch, no literature APIs (Semantic Scholar, arXiv, OpenReview, OpenAlex), no MCP servers beyond the ARIS reviewer. The only network traffic is model API calls.
- **One fresh run per item, one run only.** No benchmark repository clone sits in the workspace, since several repos hold answer keys or baseline outputs.
- **Refusal scores 0.** Report the refusal rate per system.
- **Pin every system to a commit SHA.** Record all patches as diffs in `MANIFEST.md`.

### 1.1 ARIS

- **Install**: the `dsh-aris` plugin, `dsh plugin --profile web add dsh-aris`. If it does not work on the pinned dsh version, fall back to Claude Code with the DeepSeek Anthropic-compatible endpoint (`https://api.deepseek.com/anthropic`), and record the switch.
- **Run**: `/idea-creator` only. Do not use `/idea-discovery`: its evidence gate blocks without reviewer receipts.
- **Models**: executor `deepseek-v4-flash`; reviewer gpt-6-astra through Codex MCP, which is ARIS's default cross-model design. ARIS's brainstorm is generated by the reviewer, so this condition includes GPT output. Record which steps ran on which model.
- **Output**: `idea-stage/IDEA_REPORT.md`, converted per Section 1.5.

### 1.2 ResearchStudio-Idea

- **Run**: `run.py next --dir <new dir> --query ...` in a loop, with a CLI shim that sends each stage's prompt to `deepseek-v4-flash`.
- **No live retrieval**: disable Phase 0 retrieval. For Lit2Test, inject the 4 neighborhood papers as seed references with `add_user_ref`. For PaperGym, the query is the item text, with no seeds.
- **Abstention**: the system refuses (`do_not_generate`, `phase_3_failed`) when it finds fewer than 5 related papers or no anchor. Expect frequent refusals on PaperGym. Each refusal scores 0 and is logged.
- **Pinning**: pin the commit and record `IDEASPARK_DEPTH`; a 2026-09-21 commit changed its default.
- **Output**: idea card plus detail card, converted per Section 1.5.

### 1.3 AI Scientist v2

- **Patch**: add an OpenAI-compatible client branch so `--model deepseek-v4-flash` works (about 15 lines in `create_client` and `AVAILABLE_LLMS`).
- **Token limit**: raise `MAX_NUM_TOKENS` from 4096 so outputs are not truncated. Record the value.
- **Run**: `perform_ideation_temp_free.py --workshop-file <item>.md`. Write one input file per item so `reload_ideas` never pulls in earlier ideas.
- **No live retrieval**: replace the Semantic Scholar tool with a tool that returns only the item's own input. For Lit2Test that is the 4 papers; for PaperGym, nothing extra.
- **Output**: the 7-field JSON, converted per Section 1.5.

### 1.4 claude-scientific-skills

- **Install**: the whole pack into dsh.
- **Inputs**: the same inputs, output format and per-item setup as arm C of the main experiment.
- **Prompt**: "This environment ships a library of research skills. Use them wherever they fit." followed by the benchmark input.
- **Output**: its final answer is already in the benchmark's format, so it needs no conversion step.

### 1.5 Format Conversion (ARIS, ResearchStudio-Idea, AI Scientist v2)

The native outputs do not match the benchmark formats. One separate call to `deepseek-v4-flash` converts each output with a fixed prompt:

- **Content**: move content into the target fields and do not add anything. A target field with no source content stays empty.
- **Lit2Test**: the six-field JSON.
- **PaperGym**: free text, with the system's content kept as-is.
- **Records**: store the conversion prompt in `scripts/`, and each call's input and output in the item's `answer.json`.

## 2. Benchmarks

Benchmark rules are the same as in the main plan. Summary:

| Benchmark | Items | Input given | Output | Scoring |
| --- | --- | --- | --- | --- |
| [Lit2Test](https://github.com/rrustlee/lit2test-benchmark) | 200 | Context without `url`, `decision`, `review_count`, `rating_summary`, `pool_metadata` | Six-field JSON | Pairwise, both orders, Gemini 3.1 Pro Preview; Bradley-Terry |
| [SoundnessBench](https://huggingface.co/datasets/hosytuyen/SoundnessBench) | 1,099 | Anonymized ID, `short_hypothesis`, `experiments`; standard prompt | `{justification, rigor_bucket, confidence}` | Deterministic; Macro-F1, accuracy, κ |
| [SciΠvot](https://github.com/AutoResearch-Factory/SciPIvot) options-only | 248 × 2 orders | The two rendered options only | `{argument, response}` | `score.py --ci`; plus the "pick the longer option" baseline |
| [PaperGym-Design](https://github.com/ZJU-REAL/PaperGym) | 1,200 | `prompt[0].content` from `innov.parquet` (the file names are swapped) | Free text, no length cap | gpt-6-astra rubric 0/1; record answer length |

Judging details that differ from the main plan:

- **Lit2Test**: each condition is judged against each of the 4 reference proposal sets in `results/proposals/`, in both orders. That is 4 pairs × 200 × 2 = 1,600 judge calls per system. We pair the baselines with the DARE arms later ourselves.
- **SoundnessBench and SciΠvot**: run only for `scientific-skills`.

## 3. Deliverables

Same layout as the main plan, under `dare-benchmark/baseline/` in the public HF bucket:

```text
dare-benchmark/baseline/
├── MANIFEST.md
├── scripts/                                  # driver code, shims, patches, conversion prompt (secrets redacted)
├── data/<benchmark>/                         # exact stripped inputs + sha256 (must match deepseek-glm/data/)
├── runs/<benchmark>/<condition>/<item_id>/
├── judge/<benchmark>/...
├── results/
│   ├── scores.csv
│   └── summary.md
├── CHECKSUMS.sha256
└── DONE
```

The stripped inputs must be byte-identical to `deepseek-glm/data/`. Compare the sha256 sums before running.

### 3.1 Per-item directory

| File | Content |
| --- | --- |
| `prompt.md` | The exact input given to the system |
| `transcript/` | Native logs, untouched: agent sessions, every LLM request and response, and ARIS reviewer calls |
| `workspace/` | Snapshot of the system's output directory: `idea-stage/`, idea and detail cards, ideation JSON |
| `raw_output.md` | The system's final native output |
| `answer.json` | The converted answer submitted to the scorer, plus the conversion call's input and output |
| `meta.json` | Fields: `start`, `end`, `tokens_in`, `tokens_out`, `tokens_cache`, `cost_usd` (sum of all models, reviewer tokens listed separately), `exit_status`, `error`, `abstained`, `final_attempt`, `server_model_version` |

### 3.2 Retries, judge records, scores, sync

These follow the main plan's Sections 3.2–3.6:

- **Retries**: infrastructure failures only, at most 3, all attempts kept.
- **Judge records**: one raw request and response per call. Reference sets use `ref.<model>` as the condition.
- **`scores.csv`**: the same long table, with `status` set to `abstain` for refusals.
- **Sync and freeze**: daily sync, redaction before every upload, then `CHECKSUMS.sha256` and `DONE`. Fixes go under `revision-2/`.

### 3.3 `MANIFEST.md`

Delivery is incomplete if any item below is missing.

- **Systems**: commit SHA of each of the four, plus every patch as a diff (AI Scientist v2 client branch, retrieval replacement tools, ResearchStudio shim).
- **dsh**: version, `dsh-aris` plugin version, and the fallback runtime if one was used.
- **Models**: model IDs and base URLs for `deepseek-v4-flash` and gpt-6-astra; server-reported model versions at the first and last call.
- **Settings**: per-system configs, `MAX_NUM_TOKENS`, `IDEASPARK_DEPTH`, temperatures.
- **Retrieval-off setup** for each system.
- **Format conversion**: the conversion prompt.
- **Environment**: OS, Python version, run dates.
- **Data**: stripping scripts and source data sha256.

## 4. Execution Order

```text
setup  →  smoke test  →  full runs  →  conversion  →  judging  →  results
```

- **Setup**: pin and patch the systems, disable retrieval, copy the stripped inputs and check that their sha256 matches the main experiment's `data/`.
- **Smoke test**: 5 items per benchmark per system, to confirm each one runs end to end without live retrieval. These runs are not part of the results.
- **Full runs**, then **conversion**, then **judging** (Lit2Test pairs, PaperGym rubric). SoundnessBench and SciΠvot are scored deterministically.
- **Results**: `scores.csv`, `summary.md`, checksums, `DONE`.
